# 上方山三维与 GIS 实施方案

## 1. 当前可执行目标

本阶段不预设任何未经坐标验证的点位。先把碑文中的对象整理为统一主表，再通过 QGIS 配准、影像判读和实地控制点逐步补充坐标。Blender 只使用已经进入主表、且有明确定位依据的对象。

当前主数据文件：

- `data/heritage_points.csv`：可在 QGIS、ArcGIS Pro 中作为属性表导入
- `data/heritage_points.geojson`：网页和 GIS 的交换格式；目前几何为空，表示尚未刺点
- 坐标基准：最终统一输出为 WGS 84 / EPSG:4326；分析过程可使用 CGCS2000 对应投影坐标系

## 2. 点位状态规则

| 字段 | 允许值 | 含义 |
|---|---|---|
| `area_status` | 山内 / 山外 | 是否属于上方山核心区 |
| `location_status` | 待刺点 / 待考证 / 已刺点 / 已实测 | 当前空间定位阶段 |
| `evidence_level` | 文献明确 / 文献较明确 / 文献存疑 / 地名存疑 / 位置不明 / 相对位置 / 术语存疑 | 定位证据强度 |

只有“已刺点”或“已实测”的对象，才可在网页地图中使用真实点几何。`待考证` 对象应以不确定性清单或候选范围表达，不应放置一个看似精确的坐标。

## 3. QGIS 第一轮操作

1. 加载 ASTER DEM，确认其原始坐标系为 EPSG:4326。
2. 使用 Georeferencer 配准 `data/194f95fb9a326548537182ec485a01f5.jpg`。
3. 控制点优先选取兜率寺、天梯两端、道路转折点、明显峰脊和沟谷；每个控制点记录来源和误差。
4. 将配准后的等高线图输出为 GeoTIFF，并记录变换方式、残差和输出 CRS。
5. 加载 `heritage_points.csv` 时先作为非空间表导入；获得经纬度后再按 `longitude`、`latitude` 创建点图层。
6. 将确认后的点图层导出为 GeoJSON，覆盖交换文件前保留原始版本。

第一轮只处理：`SF01` 兜率寺天梯、`SF02` 兜率禅寺、`SF03` 文殊殿、`SF04` 普贤殿。它们构成 Blender 核心场景的最低可信范围。

## 4. ArcGIS Pro 后续分析

- 由 DEM 派生坡度、坡向和山体阴影。
- 分析天梯到兜率寺的高差和可达路径。
- 按唐、辽、金、明、清制作历史时期图层。
- 对“山内”与“山外”点位使用不同图层和符号。
- 将确认后的点位、建筑轮廓和道路导出为 Blender 可读取的 GeoJSON 或 CSV。

## 5. Blender 建模规则

### 第一阶段：核心低模

只建模兜率寺、天梯、文殊殿、普贤殿及其所在山体。建筑采用模块化组件，保留院落、台阶、屋顶和主要体量，不先做复杂纹样。

### 第二阶段：证据分级表现

- 文献明确且有实测：实体材质
- 文献明确但仅影像判读：低饱和材质，并在属性中注明
- 仅由方位关系推测：半透明或线框
- 位置存疑：不建实体，只保留 GIS 标记

### 第三阶段：输出

Blender 输出 GLB/GLTF，用于网页或三维展示；高质量静帧用于报告插图。模型坐标必须与 GIS 导出的 EPSG:4326 或统一局部投影坐标对应，并在项目记录中写明原点、单位和旋转方式。

## 6. 当前数据口径说明

现有文献目录存在 17 篇、18 个点位和 19 个空间/人物对象的不同口径。新主表暂按 19 个对象分别编号：既保留建筑、道路、洞窟和塔，也保留道目禅师这一“人物活动关联点”。正式报告应明确区分“文献篇目”“空间对象”和“可定位点位”，不能把三者直接等同。

## 7. 下一次外业或判读应记录

- 点位编号和名称
- 经纬度、采集方式、设备和时间
- 高程及高程来源
- 照片编号与朝向
- 是否为现存遗迹、推定遗址或文献关联位置
- 定位误差和仍待解决的问题
